# 会话切换（枪管与弹巢）

> 枪管是渠道，弹巢是会话。用户永远只看见枪管，平台在下面决定这句话装进哪个弹巢。

## 一、三层模型

```
agent  →  conversation（窗口，用户唯一感知）  →  session（弹巢，可多个）
```

| 层 | 存在哪 | 作用 |
|---|---|---|
| conversation | `data/conversations.json` | 这个窗口**现在对准**哪个会话（指针） |
| session | `data/sessions.json` | 有哪些会话、标题、接续关系 |
| 消息 | `~/.pi/agent/sessions/*.jsonl` | 真正的上下文，pi 读它 |

指针为什么单独存：它频繁变，混进会话表会让每次切换都整篇重写；
更关键的是**指针不能存在会话里**（会话会变，指针得跟着变）。

## 二、开关

写在 `agents/<id>/waker.yaml`：

```yaml
session:
  mode: topic        # single（默认，旧行为）| topic | timeWindow
  idleSplitHours: 8  # 多久没动才考虑"这是新话题"；0 = 不看时间
  ask: always        # always = 先问；never = 直接切并告知
  rejectLimit: 2     # 连续拒绝几次后不再问（退化为不切）
  autoSwitch: false  # false = 永不自动落指针：一律先问；缺省 true
```

- `single`：完全不读 `conversations.json`，走旧的 `resolveSessionByKey`，零行为变化
- `topic`：读指针表，按话题换弹巢
- `autoSwitch: false`：**不许脚自己挪**。判定为 NEW / SWITCH 时一律发询问卡，
  `rejectLimit` 与 `ask: never` 都不再能绕过它（`decideAskGate` 里它最先判）。
  当前 `chat` 就是这种配置

**回退语义**：topic → single 时，按 externalKey 找到的是**首个弹巢**（这个渠道最早那个会话），
即"冻结路由回到原点"，不会停在中途某个话题上。

## 三、判定规则：显式指令 → 向量召回 → 小模型仲裁

判定分三层，按顺序短路（2026-10-25 加第三层）：

| 层 | 谁做 | 作用 | 耗时 |
|---|---|---|---|
| 1. 显式指令 | `matchExplicitNewTopic`（正则） | 句首「新话题 / 换个话题 / 说点别的 / 另一个话题」→ 直接开新弹巢，**不问也不调模型** | 0 |
| 2. 召回 | `semanticInputFor`（bge-m3） | 把候选会话缩到 ≤8 个，供第 3 层挑；同时算阈值分数备用 | ~40ms |
| 3. 仲裁 | `topicArbiter.arbitrate`（laya，449MB 常驻，decision 型） | 走决策模型专用接口 `POST /v1/systemone`，对 `action`（continue/new/switch）与 `target`（c1..c5/none）各取一个 choice，翻成置信度 0.9 / 0.75 / 0.75 | 176~265ms |

**为什么必须加第 3 层**：向量只能回答"像不像"。实测 50 条路由里 **46% 落在 0.42~0.58 的模糊带**，
而模糊区的置信度封顶 0.45，低于调用方 0.5 的门槛——结果既不切也不问，静默留在原会话。
最典型的一条：用户只发「新话题」三个字，它与 42 条的创业会话余弦 **0.55**
（语义上没错，两段都在谈"聊天"），但它是**指令**不是**内容**，向量空间里没有这个维度。

**降级顺序**（任何一步失败都不阻断对话）：

- 仲裁返回 null（关配置 / 模型没加载 / 超时 6s / 输出解析不了）→ 退回下面的阈值判定
- **laya 只能走 `/v1/systemone`**：它是 ModernBERT 决策模型（`type: decision`），
  `/v1/chat/completions`、`/v1/completions`、`/v1/responses` 一律回 `No models loaded`
  （那句话的意思是"没有 llm/vlm 实例"，不是没加载）。换对话小模型时把 `arbiter.api` 设成 `chat`
- **决策模型的输入上限 512 token（单个物理 batch）**：双向编码器不能分批喂 context，
  state 342 字 = 565 token 直接被拒。所以 systemone 的 state 按 220 字硬裁，超预算先砍候选
- 1~2 个字的短消息不送模型：实测「b」（回答上一轮选项）被判成 NEW，白开一个弹巢
- 仲裁置信度固定 0.75 / 0.9，**不假装 0.95**；落不落指针仍由询问卡决定

### 阈值判定（降级时使用，或 `arbiter.enabled: false`）

`src/core/topicRouter.ts` 是纯函数（不读文件、不调模型），但可以接收**向量**：

| 情形 | 用什么判 | 说明 |
|---|---|---|
| 向量可用 | **语义**（余弦） | 主判据，能处理"同义不同词" |
| 向量不可用 | 词面（字二元组 Jaccard） | 降级路径，服务挂了不中断功能 |

两套阈值是**不同的刻度**，routing 流水里用 `signals.regime` 标明本次用的是哪套——
不标的话，调参会拿词面阈值去解释语义分数。

### 语义模式（默认）

一次批量请求拿全部向量：本句 + 当前会话的若干**语义块** + 各候选会话的若干语义块。
每个会话的相似度取**块间最大值**，不做平均。

为什么必须分块：一个会话常混着多个话题（旧金山 / linkdin / AI 工具）。拼成一段求向量会被
平均掉——实测「旧金山有哪些小众景点」对这样的会话只有 **0.574**，按块取最大是 **0.802**。
块 = 标题 + 会话卡摘要 + 话题起点 + 最近三条用户消息（最多 5 块）。

判定顺序与词面模式完全一致：

1. `余弦(本句, 当前) ≥ 0.58` → **继续**
2. 命中另一会话且 `≥ 0.60` 且高出当前 `0.08` → **切回旧话题**
3. 间隔 ≥ `idleSplitHours` 且与当前 `< 0.45` → **新话题**
4. 其余 → **继续**，置信度压到 0.45 以下

阈值按 bge-m3 实测标定（2026-10-23）：

| 文本对 | 余弦 |
|---|---|
| 无关文本基线 | 0.38 ~ 0.44 |
| 同话题换词（"标题太书面了改得更像聊天"） | 0.66 |
| 旧话题换词（"上次说的那趟日本行"） | 0.64 |

换成别的 embedding 模型必须重新标定，否则会系统性误判。

**已知局限**：长会话（几十轮、多个话题）抽样 5 块仍可能漏掉早期话题——例如一个 58 条消息的
会话里「播客」只出现在很早的几轮，按块也命中不到（实测 0.568，差 0.01 到切换线）。
此时判定会 fail-open 留在当前会话，用户可用网页会话列表或 IM 的 `/topics` `/resume` 手动切。
会话卡生成后会被当成一个语义块加进来，能部分缓解这个问题。

### 词面模式（降级）

1. 与当前重合 ≥ `0.12` → 继续
2. 命中另一会话 ≥ `0.22` 且高出 0.08 → 切回
3. 间隔 ≥ `idleSplitHours` 且重合 < `0.04` → 新话题
4. 其余 → 继续，置信度压到 0.45 以下

中文按字二元组切词，虚词先剔除。它的天花板是"同义不同词"会漏判——
实测"标题太书面了"对播客会话的词面重合只有 0.03，语义是 0.66。

### 置信度与"敢不敢动用户的会话"

- **仲裁层给出的分数**：CONTINUE 0.9、NEW/SWITCH 0.75。都过 0.5 门槛，因此会进询问卡；
  但故意不给 0.95——那是"我很确定"的说法，小模型给不了
- 置信度 < 0.5：**一律不切**，静默在当前会话作答（fail-open）
- `autoSwitch: false`：一律先问，不看下面的两条（拒绝配额用尽也只是**留在当前会话**）
- 置信度 ≥ 0.5 且 `ask: always`：先问；连续拒绝达 `rejectLimit` 后不再问，也不切
- 置信度 ≥ 0.5 且 `ask: never`：直接切并告知

判定顺序也是刻意的：三者错误代价不对等。误继续只浪费 token；
误开新会话会让用户觉得"它忘了刚才"，所以"继续"永远先判。

## 四、IM 里的对话流程

```
用户：接着上次那个播客标题，再口语一点
   ↓ 判定 = switch，置信度够
机器人（卡片）：
        **这句像是在聊《播客标题》**
        最后活动：3 小时前
        **上次到这里**
        你：这个标题再口语一点
        ——————————
        要切回那边继续吗？
        [ 切回去 ]  [ 就在这儿继续 ]      ← 真按钮（正文不再重复写「回 1 / 回 2」）
用户：点「切回去」（也可以直接回 1 / 2，文字路径仍在）
   ↓ 卡片**当场**换成：✅ 已选择：切回去
                      ⏳ 正在接着回答，结果稍后出现在下面…
     同一刻弹 toast「已选择：切回去，正在处理…」；按钮消失，点不到第二次
机器人：**已切到《播客标题》**
        上次到这里：……
        你说：「接着上次那个播客标题，再口语一点」
        ────────
        （真正的新回答）
   ↓ 答完把卡片刷成终态：✅ 已选择：切回去 · 已处理完成
```

要点：

- **判定在写入之前**。确认前不调用模型、不写任何会话，所以不会出现"两个会话各留一份"。
- **确认后直接作答**：把原话带过去一并回答，用户不必重说一遍。
- **只读不写地留痕**：源会话记 `transferredTo`，表示"这句已转走"，但**不删消息**
  （pi 的 jsonl 只追加，删改会破坏 entry 引用链——这是 v1 踩过的坑）。
- `ask: never` 时跳过询问，但**告知不能省**：用户必须知道自己现在在哪。
- **按钮不是唯一入口**。按钮依赖租户在开发者后台订阅 `card.action.trigger`，
  没订阅时点了没反应；所以「回 1 / 回 2」的那行字仍然保留 —— 但**只出现在纯文本退路里**
  （卡片发送失败回落纯文本时才可见）。卡片正文只放问题本身：正文写着"回 1 / 回 2"、
  下面又摆着按钮，是重复，实测用户一眼就挑了。
- 卡片结构按**卡片 JSON 2.0**：`button` 直接放在 `body.elements`（不套 1.0 的 `action` 容器），
  回调值走 `behaviors: [{type:'callback', value}]`。混用版本会被接口整条拒收。
- 回调**必须立刻返回**：ack 迟到会被飞书重投（与 IM 消息同一个坑），
  所以入口只 fire-and-forget，回复走 REST 另发一条。
- **点完必须有反馈**（实测反馈：按钮不变灰、不显示点了什么，像卡死）。ack 里顺手带回
  **新卡片**（`card: {type:'raw'}`，本地生成、不发请求）：按钮**整个删掉**
  （2.0 的 `button` 没有 disabled 语义，删掉才真的点不到）+ 「✅ 已选择：X」+ ⏳ 进度。
  三种例外：会话忙 → 保留按钮只给警告 toast（刷成"处理中"就是撒谎）；
  提问已失效 → `expired` 态；处理抛错 → `failed` 态。
- 答完用 `im.v1.message.patch` 把卡片刷成终态，**best-effort**：这步依赖额外接口能力/权限，
  失败只记日志——答案的回复已经发出去了，卡片停在 ⏳ 也不丢信息。

## 四之二、网页对话窗（与 IM 同一套语义，载体不同）

```
用户：在对话窗里输入「那个开发板项目…传感器换成 ToF」
   ↓ 发送前先调 POST /api/agents/chat/:id/route（只判定，不写会话）
   ↓ continue → 直接发；switch → 弹建议条；new → 弹开新话题条
建议条：
        [话题] 这句像是在聊《esp32-cam》（相似度 0.56）
               上次到这里：……
               [切过去并发送]  [就在这儿发]  [×取消（这条不发出）]
   ↓ 点「切过去并发送」→ 头部话题立刻变成目标会话，落一行
     「已切到《X》，正在按你刚才那句回答…」→ 答完变「已处理完成」
```

要点：

- **判定延迟**：`/route` 现在 1.2s 冷启动 / 160ms 热。冷启动来自 embedding 批量（10 会话 ≈ 40 块）；
  之前超时 2s，实际要 3.4s，于是每次都降级成词面、建议永远弹不出来。现在超时 6s + 候选块限量 + 分两批。
- **建议线比 IM 宽 0.05**（`WEB_SUGGEST_MARGIN`）：网页弹的是可点可不点的建议条，误判代价是一次点击；
  IM 要动指针、耗询问配额，必须更保守。仍然不改任何会话状态，接受才动 `activeId`。
- **`new` 也要弹**：判定器给 `new` 时提示「开新会话并发送」，与飞书「要开一个新话题吗」对齐。
  `new` 仍受 `idleSplitHours` 约束——同一段活跃对话里不会隔三差五建议你开新会话。
- **有待确认建议时禁止发送**：否则会叠出第二条建议，第一条孤零零挂在那儿。
- 网页端**也走小模型仲裁**（与 IM 同一条 `arbitrate()` 链路，约 200ms）。仲裁判「新话题」时再加一道向量闸门：向量认为明显还在当前话题就不弹——建议条是主动打断，误弹一次就是一次打扰。

## 五、命令（仅 topic 模式暴露）

| 命令 | 作用 |
|---|---|
| `/topics` | 发一张**折叠卡片**：每条一个可展开面板（标题 + 相对时间 + 条数），展开看会话卡摘要，非当前项带「切到这儿」按钮。卡片发不出去时回落纯文本，每行仍带序号、标题、时间条数、摘要首句 |
| `/resume 序号` | 切回某个历史话题，并给出"上次到这里"摘要；序号与卡片顺序完全一致，点到当前话题只说"不用切" |
| `/new [标题]` | 显式开新话题，不询问 |
| `/back` | 退回上一个话题 |
| `/clear` | 清空当前会话上下文（会话保留） |

**标题从哪来**（决定列表好不好认）：建会话时先截用户首句前 18 字（`nameFrom: 'derive'`），
模型第 3 轮起名后升到 `messages`，会话卡生成后用卡的第一行升到 `card`。
升级单向、`manual` 永不覆盖；存量数据没有 `nameFrom` 时只有"明显没人起过"的名字才会被卡覆盖。

## 六、观测：怎么确认真的切了

```bash
node scripts/watch-sessions.mjs          # 实时跟随
node scripts/watch-sessions.mjs --last 8 # 回放
```

- `🔀` 本轮与上一轮的文件不同 —— 切换的硬证据
- `⏺` 同一文件 —— 没切
- `⤳` 文件名相同但目录变了 —— 迁移换 home 的痕迹，不计入切换

判定流水在 `data/routing.jsonl`，每条含信号、置信度、决定与理由：

```bash
tail -1 data/routing.jsonl | node -pe 'JSON.stringify(JSON.parse(require("fs").readFileSync(0,"utf8")),null,2)'
```

## 七、验收判据（C1–C5）

| 判据 | 期望 |
|---|---|
| C1 | 两条记录的 `sessionRef` 不同 |
| C2 | 目标文件 mtime 更新 |
| C3 | **源文件 mtime 不变**（没被顺带污染） |
| C4 | 回答里出现只在目标会话存在的专名 |
| C5 | 用户看到切换告知 |

C3 最容易漏，也最容易出隐性 bug。当前实现因为"确认前不写入"，C3 天然成立。

## 八、边界（明确不做的）

| 项 | 状态 | 原因 |
|---|---|---|
| 向量召回旧话题 | 未做 | 需要记忆服务，判定层刻意不依赖外部服务 |
| LLM 生成摘要 | 未做 | 询问路径上不能有第二次推理；现在是"最近两轮原文截断" |
| 网页端建议条拒收计数 | 未做 | IM 有 `rejectLimit`（连续拒绝就不再问）；网页每次都是单条建议条，暂不做配额 |
| 群聊按发言人分指针 | 未做 | 群是一个窗口，目前整群共用一个指针 |
| 时间窗自动切分 | 未做 | 需要独立开关，先验证询问式够不够 |
| 跨 agent 共享话题 | 不做 | 会话是权限作用域的产物，迁移会越权 |
